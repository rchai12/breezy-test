# Spec 03: Automated Test Harness

## Context
The Breezy site is a static site with no build step: `breezy-intern-test.html` (homepage), `css/`, `js/`, and a four-page signup flow in `signup/`. Phase 1 (`specs/02-signup-phase1-foundation.md`) and the FAQ fix (`specs/01-faq-accordion-fix.md`) are done, and so far they have only been verified by hand.

This phase adds automated tests in two layers:
1. **Unit tests** for pure logic, using Node's built-in test runner (`node --test`). No extra packages.
2. **Browser tests** using Playwright in **Chromium only**, loading the pages as `file://` URLs, the way a reviewer opens them.

A GitHub Actions workflow runs both on every push and pull request.

From now on, every phase spec lists the tests it must add. This phase converts the existing manual acceptance tests into automated ones.

## Hard constraints
- **The site must keep working with no build step and no server.** Tests are development tooling only. Nothing in `breezy-intern-test.html`, `signup/`, `css/` or `js/` may depend on Node or npm.
- **Don't change site code to make tests pass,** with one exception: the small refactor of `js/plans-data.js` in section 3. If a test reveals a real bug in site code, mark that test `test.fixme(...)` with a one-line comment naming the bug, and list it in your report. Do not fix it in this phase.
- **Code style:** 2-space indentation, `const`/`let`, arrow functions, semicolons. CommonJS (`require`) in test files and configs, to avoid ESM configuration. Test names are plain sentences describing behavior ("closes the open question when it is clicked again").
- **Deterministic tests only.** No `waitForTimeout` or sleeps. Use Playwright's auto-waiting assertions (`await expect(locator).toHaveClass(...)`) and Node's mock timers.

Install with `npm install --save-dev --save-exact @playwright/test`, then `npx playwright install chromium`. Node ≥ 22 is required because `node --test` expands the glob pattern itself, which keeps the script working on Windows and Linux.

## 2. Unit test helper: `tests/unit/helpers/browser-env.js`
The site scripts are browser scripts that attach to `window.Breezy`. Load them into an isolated `node:vm` context that imitates just enough of a browser. Don't modify the scripts or add export code to them.

Export:
```js
makeStorage()          // in-memory Storage: getItem, setItem (stores String(value)), removeItem, clear
makeBlockedStorage()   // every method throws new Error('storage blocked')
loadScripts(names, options) // names: e.g. ['plans-data', 'flow-state'] → js/<name>.js, loaded in order
```
`options`: `{ search = '', sessionStorage = makeStorage(), localStorage = makeStorage() }`.

`loadScripts` builds a context where:
- `window` is the context itself (`context.window = context`), so `window.Breezy` and bare `Breezy` both resolve.
- `window.location = { search, replace(url) { replaced.push(url); } }`.
- `sessionStorage`, `localStorage`, `console`, `URLSearchParams` are provided.
- `setTimeout` / `clearTimeout` are **wrappers that call the global at call time** (`(...args) => setTimeout(...args)`). Node's mock timers replace the global after the context is created, and the wrapper is what lets them reach the scripts.

It returns `{ Breezy: context.Breezy, replaced, context }`. Passing the same storage object into two `loadScripts` calls simulates navigating to another page in the same tab.

## 4. Unit tests
Use `node:test` (`describe`, `it`, `beforeEach`, `mock`) and `node:assert/strict`. Each test gets a fresh `loadScripts` context.

### `plans-data.test.js`
- `list` has ids `['casual', 'power', 'enterprise']` in that order. Only `enterprise` has `selfServe: false`. Only `power` has `trialDays: 7`; the others have `0`.
- `get('power')` returns the Power plan; `get('nope')`, `get(null)` and `get(undefined)` return `null`.
- `formatPrice`: `900 → '$9'`, `2900 → '$29'`, `2950 → '$29.50'`, `0 → '$0'`.
- `comparison` has 7 rows with ids in order: `breaths, blends, nostrils, support, airReport, sso, sla`.
- `_findDataErrors(comparison)` returns `[]`.
- `_findDataErrors` reports a row missing a plan id, and a row with a numeric value (build test rows inline).
- Freezing: `Object.isFrozen` is true for `list`, each plan, `comparison`, each row, and each row's `values`. Assigning to a frozen property inside the vm context does not change it.
- Loading the script calls `console.error` zero times. Pass a `console` whose `error` is a `mock.fn()` and check `callCount()`.

### `flow-state.test.js`
Load `['plans-data', 'flow-state']`.
- `readPlanParam()`: `?plan=power → 'power'`, `?plan=casual → 'casual'`, and `?plan=enterprise`, `?plan=bogus`, `?plan=` and no query all → `null`.
- **Guards with empty state:** `guard('plans')` → `true`, no redirect. `guard('register')`, `guard('payment')`, `guard('confirmation')` each → `false` with `replaced` equal to `['plans.html']`.
- **With `planId: 'power'`:** `register` → `true`; `payment` → `false`, redirect `register.html`; `confirmation` → `false`, redirect `register.html`.
- **With plan and account:** `payment` → `true`; `confirmation` → `false`, redirect `payment.html`.
- **With `subscription` set:** `confirmation` → `true`.
- **With `planId: 'enterprise'`:** `register` → `false`, redirect `plans.html`.
- `update({ password: 'x' })` throws an error whose message contains `password`. The state is unchanged afterwards.
- `get()` returns a copy: mutating it doesn't change the next `get()`.
- `clear()` resets to `{ version: 1, planId: null, account: null, subscription: null }`.
- **Persistence:** `update({ planId: 'casual' })`, then call `loadScripts` again with the same `sessionStorage` → `get().planId === 'casual'`.
- Damaged saved data (`'{bad json'`) and a wrong `version` (`{"version": 2, "planId": "power"}`) both load as the empty state.
- **Blocked storage** (`makeBlockedStorage()`): `storageAvailable === false`; `update` and `get` still work in memory; nothing throws.

### `mock-api.test.js`
Load `['plans-data', 'flow-state', 'mock-api']`. Use `mock.timers.enable({ apis: ['setTimeout'] })` in `beforeEach` and `mock.timers.reset()` in `afterEach`.
- `ERRORS` is frozen and has exactly the five codes from spec 02.
- **Latency:** start `createAccount({})`. After `mock.timers.tick(399)` it has not settled (track with a flag set in `.then`). After `tick(501)` more (900 ms total) it has resolved.
- `createAccount`, `tokenizeCard` and `createSubscription` each **resolve** (not reject) to `{ ok: false, error: { code: 'NOT_IMPLEMENTED', message: <string>, fields: {} } }`.
- `resetDb()` removes the `'breezy.db'` key from `localStorage` (seed it first) and resolves without delay (it's synchronous).

These `NOT_IMPLEMENTED` tests will be replaced when Phases 3 and 4 implement the functions. Name them "... is a stub until Phase N" so that's obvious.

## 5. Playwright setup

### `playwright.config.js`
```js
const { defineConfig, devices } = require('@playwright/test');

module.exports = defineConfig({
  testDir: 'tests/e2e',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  reporter: process.env.CI ? [['github'], ['html', { open: 'never' }]] : 'list',
  use: { trace: 'on-first-retry' },
  projects: [{ name: 'chromium', use: { ...devices['Desktop Chrome'] } }],
});
```
No `webServer`. Pages load as `file://` URLs.

### `tests/e2e/helpers.js`
Export:
- **`test` and `expect`:** Playwright's `test` extended so every test fails if the page logged a console error or threw an uncaught error:
  ```js
  const test = base.extend({
    page: async ({ page }, use) => {
      const errors = [];
      page.on('pageerror', err => errors.push(err.message));
      page.on('console', msg => {
        if (msg.type() !== 'error') return;
        const url = msg.location().url || '';
        if (/fonts\.(googleapis|gstatic)\.com/.test(url)) return; // offline font loads aren't our bug
        errors.push(msg.text());
      });
      await use(page);
      expect(errors, 'console errors').toEqual([]);
    },
  });
  ```
  All spec files import `test` and `expect` from here, not from `@playwright/test`.
- **`fileUrl(relPath, search = '')`:** `pathToFileURL(path.join(ROOT, relPath)).href + search`, where `ROOT` is the repo root.
- **`seedFlow(page, state)`:** `page.addInitScript` that writes `{ version: 1, planId: null, account: null, subscription: null, ...state }` to `sessionStorage['breezy.signup']` before any page script runs. It must run only once per test. Guard it with a `sessionStorage` marker key, or the seed would overwrite state on every navigation.
- **`SAMPLE`:** fixtures `SAMPLE.account = { accountId: 'acc_test', name: 'Ada Breath', email: 'ada@example.com' }` and `SAMPLE.subscription = { subscriptionId: 'sub_test', planId: 'power', status: 'trialing', startedAt: '2026-09-30T12:00:00.000Z', firstChargeAt: '2026-10-07T12:00:00.000Z', amountCents: 2900, card: { brand: 'visa', last4: '4242' } }`.

## 6. Browser tests

### `faq.spec.js` (homepage)
Use locators `page.locator('.faq-q').nth(i)` and the answer `.faq-a` in the same `.faq-item`.
- All questions start closed.
- Clicking Q1 opens it: the button and the answer both have class `open`.
- Clicking Q1 again closes it: neither has `open`.
- Clicking Q1 then Q3: Q1 is closed and Q3 is open.
- Clicking all five in order: after each click, exactly one `.faq-a.open` exists, and it belongs to the question just clicked.
- Keyboard: focus Q2 and press Enter to open it, then Enter again to close it.
- After any sequence of clicks, every `.faq-q` has `open` exactly when its `.faq-a` does (loop over all five).

### `routing.spec.js`
**Entry points** (desktop viewport 1280×800). One test per row. Each clicks the element and asserts the final URL ends with the expected path:
| Element (locate by role/name) | Expected URL ending |
|---|---|
| link "Start Breathing Better →" | `signup/plans.html` |
| link "Get Started" | `signup/plans.html?plan=casual` |
| link "Start Free Trial" | `signup/plans.html?plan=power` |
| mid-bar link "Book Air" | `signup/plans.html` |

- **Mobile Book Air** (viewport 390×844): click the hamburger (`#hamburgerBtn`), then the "Book Air" link inside `#mobileMenu` → URL ends with `signup/plans.html`.
- **Preselection placeholder:** `?plan=power` shows the text "Preselected: Power Inhaler". `?plan=enterprise` and no query show no "Preselected" text. *(Phase 2 replaces this placeholder and must update these tests.)*
- **Buttons that stay on the homepage:** "▶ Watch the Story" and "Contact Sales" each make `#toast` get class `show` with the matching message text, and the URL doesn't change. "Subscribe Free →" with an empty email shows the "valid email" message; with `a@b.co` it shows the welcome message and the input is cleared.
- **Brand link:** on each of the four signup pages (seed state so the guards allow them), clicking the "Breezy" brand link goes to `breezy-intern-test.html`.

### `guards.spec.js`
- With empty state, opening `register.html`, `payment.html` and `confirmation.html` directly each lands on `plans.html`.
- **Redirects don't add history:** open the homepage, then go to `signup/payment.html` (it redirects to `plans.html`), then `page.goBack()` → the URL is the homepage, not `payment.html`.
- Seeded `{ planId: 'power' }`: `register.html` stays; `payment.html` → `register.html`.
- Seeded `{ planId: 'power', account: SAMPLE.account }`: `payment.html` stays; `confirmation.html` → `payment.html`.
- Seeded `{ planId: 'enterprise' }`: `register.html` → `plans.html`.
- Each page's title and `h1` match spec 02, and the step marked `aria-current="step"` is the right one (Plan / Account / Payment / Done), with earlier steps `.is-complete`.

### `state.spec.js`
- **Cross-page persistence (Chromium, `file://`):** on `plans.html`, run `page.evaluate(() => Breezy.flow.update({ planId: 'power' }))`, navigate to `register.html` → it stays there, and `Breezy.flow.get().planId === 'power'`. The `.storage-warning` banner is hidden.
- **Blocked storage shows the warning:** use `page.addInitScript` to make `window.sessionStorage` throw (`Object.defineProperty(window, 'sessionStorage', { get() { throw new DOMException('blocked', 'SecurityError'); } })`), open `plans.html` → `.storage-warning` is visible and there are no console errors.
- **`update` rejects unknown keys in the real page:** `page.evaluate` a call to `Breezy.flow.update({ password: 'x' })` inside a try/catch, returning the error message → it contains `password`.

### `layout.spec.js`
For every combination of page × width, assert no horizontal page scrolling:
```js
const overflow = await page.evaluate(() => document.documentElement.scrollWidth - window.innerWidth);
expect(overflow).toBeLessThanOrEqual(0);
```
- Pages: the homepage, and `plans.html`, `register.html`, `payment.html`, `confirmation.html` (seed `{ planId: 'power', account: SAMPLE.account, subscription: SAMPLE.subscription }` so none redirect).
- Widths: 360, 768, 1280 (height 800).
- Also at 360px on each signup page: the step indicator's four step numbers are visible (each `li` has a non-zero bounding box).

If the **homepage** fails at 360px, that's a pre-existing issue. Mark that case `test.fixme` with a comment, report it, and don't fix it here.

## 7. CI: `.github/workflows/test.yml`
```yaml
name: Tests
on:
  push:
  pull_request:
jobs:
  test:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npm run test:unit
      - run: npm run test:e2e
      - uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: playwright-report
          path: playwright-report/
          retention-days: 7
```

## Acceptance criteria
1. `npm test` passes locally on Windows, with the only exceptions being tests marked `test.fixme` for pre-existing bugs, each listed in your report.
2. `npm run test:unit` finishes in under 2 seconds (mock timers, not real delays).
3. **Proof the tests catch regressions.** Temporarily make each of these changes, confirm the named test fails, then revert. Don't commit these changes.
   - In `js/home.js`, change `toggleFaq` back to only adding `open` → the FAQ close tests fail.
   - In `breezy-intern-test.html`, change the "Start Free Trial" link to `?plan=casual` → the routing test fails.
   - In `js/flow-state.js`, make `guard('payment')` skip the account check → the guard tests fail (unit and browser).
   - In `css/signup.css`, give `.signup-main` `min-width: 500px` → the 360px layout tests fail.
4. There are no `waitForTimeout` calls and no `test.only`.
5. The workflow file is valid YAML and uses only the actions listed above. **Do not push.** The user pushes and checks the first CI run.

## Not covered (stays manual)
- **Firefox and Safari.** Only Chromium is tested, by choice. Whether Firefox keeps signup progress between pages when the files are opened directly is still unverified. Phase 6's README will document the `python -m http.server` fallback.
- Visual appearance (colors, spacing, the footer's gray text). Tests check behavior and overflow, not looks.
